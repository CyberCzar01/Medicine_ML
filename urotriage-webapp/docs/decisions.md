# Журнал решений — urotriage-webapp

Здесь фиксируются все принятые идеи и решения по мобильному веб-приложению. Формат: решение → почему.

## 2026-07-05 — старт проекта

**Что строим.** Мобильное веб-приложение (PWA) для врача-уролога: быстрый ввод анкеты пациента с ОЗМ/ДГПЖ + мгновенный светофор. Главная цель первой версии — сбор данных для дообучения модели, но для врача приложение подаётся как рабочий инструмент со светофором. Про научную цель в интерфейсе не говорим (решение заказчика).

**Целевая платформа.** Android и iPhone через браузер. PWA: manifest + service worker, ставится на главный экран («Установить приложение» в Chrome на Android). Нативное приложение не пишем — веб покрывает обе платформы и не требует магазинов.

**Архитектура: отдельный проект рядом с botkin-urotriage** (выбор Фёдора). Свой FastAPI-сервер: отдаёт статику PWA, хранит записи в SQLite, за светофором ходит по HTTP в существующий API (`UROTRIAGE_API_URL`). В код botkin-urotriage не лезем — он отдаётся заказчику как есть.

**Вход: без авторизации** (выбор Фёдора). Компромисс для атрибуции записей: необязательное поле «Врач» в Сводке, хранится в localStorage устройства и подписывает каждую запись. Не пароль, просто подпись.

**Светофор показываем сразу** (выбор Фёдора): живой чип зоны прямо в форме (пересчёт на лету через `/api/triage`, дебаунс 600 мс) и полный разбор после сохранения. Это главный стимул врачу не откладывать ввод: он получает пользу немедленно.

**Персональные данные: только № истории болезни** (выбор Фёдора). ФИО не вводим и не храним — проще с 152-ФЗ, для обучения модели ФИО не нужны. Идентификация — case_id вида «91-2025-С», как в текущей Excel-анкете.

## Принципы UX (чтобы врач не откладывал ввод)

1. Обязательное поле одно — № истории болезни. Всё остальное можно пропустить и дозаполнить позже. Частичная запись лучше отсутствующей.
2. Никакого визарда по шагам — одна прокручиваемая форма из 7 коротких блоков. Пролистать быстрее, чем кликать «Далее».
3. Всё, что можно, — чипы и сегменты вместо клавиатуры. Клавиатура только для чисел (numeric keypad, `inputmode`) и двух текстовых полей.
4. Черновик автосохраняется в localStorage на каждый ввод — случайно закрытая вкладка ничего не теряет.
5. Офлайн-очередь: если сети нет, запись ложится в outbox и уходит сама при появлении сети. Save никогда не «падает» для врача.
6. Сохранение не зависит от светофора: если API светофора лежит, запись всё равно сохраняется, зона досчитается потом.
7. Кнопка «Дозаполнить исход» — отдельный короткий сценарий: врач при выписке открывает пациента из списка и вносит 5 полей.

## Структура разделов (нижняя навигация)

1. **Новый пациент** — форма, блоки: Поступление → Жалобы и диагноз → Анамнез → Объективно → Лаборатория → УЗИ → Дренирование. Sticky-панель снизу: живая зона + «Сохранить».
2. **Пациенты** — поиск по № истории, фильтры (Все / Без исхода / Красные / Жёлтые / Зелёные), список с зоной-индикатором. Карточка пациента: данные, разбор светофора, «Дозаполнить исход», «Редактировать».
3. **Сводка** — счётчики (всего, за 7 дней, по зонам, без исхода), «Экспорт в Excel», поле «Врач», статус API светофора.

## Поля формы и их судьба в данных

Набор полей повторяет Excel-анкету (survey_clean.csv) минус ФИО, плюс структурные варианты текстовых признаков. Ключи payload: case_id, admitted_at, age, onset_category, complaints_flags, complaints_text, diagnosis_text, disease_duration_years, prior_ozm_count, prior_residual, bladder_stones, prior_prostate_surgery, alpha_blockers, reductase_inhibitors, psa, temp, bp_sys, bp_dia, pulse, wbc, hemoglobin, creatinine, urea, crp, pct, prostate_vol, median_lobe, median_lobe_size, residual_urine_ml, hydronephrosis, imaging_text, drainage_method, catheter_attempt, doctor + блок исхода (had_operation, operation_txt, hours_to_oper, outcome_txt, complications_txt, readmission).

## Стыковка структурных полей с правилом светофора

Правило (`rule.py`) ищет признаки в тексте по regex. Чипы и сегменты формы конвертируются в канонические фразы, которые эти regex гарантированно ловят:

- чип «невозможность самостоятельного мочеиспускания» → та же фраза (complaint_retention, когорта);
- чип «выраженная боль» → «выраженная боль» (severe_pain → жёлтый);
- чип «макрогематурия» → «макрогематурия» (hematuria_any);
- чип «сгустки крови в моче» → «макрогематурия со сгустками» (hematuria_severe → красный);
- катетеризация «не удалась» → «безуспешная попытка катетеризации» в клинический текст (failed_catheter → красный). Фраза «катетеризация не удалась» regex-ом НЕ ловится — поэтому канонизируем;
- гидронефроз: сегмент → «двусторонний гидронефроз» / «односторонний гидронефроз» (красный) / «пиелоэктазия» (жёлтый) / «гидронефроза нет» (отрицание правило понимает);
- остаточная моча идёт и числом (residual_urine_ml), и строкой в imaging_text.

Это осознанная связка: если паттерны в config.py поменяются, фразы в webapp надо перепроверить (см. tests).

## Хранение

SQLite (`data/records.db`), таблица records: id, case_id, created_at, updated_at, doctor, payload (JSON), triage (JSON-ответ API), zone, outcome_filled. JSON-payload вместо 40 колонок — форма будет меняться после разговора с врачом, миграции не нужны. Экспорт в Excel разворачивает JSON в колонки в порядке текущей анкеты. `data/` в .gitignore — медицинские данные в git не кладём (правило проекта).

## Перенос localhost → домен без доработок

- Фронтенд ходит только на относительные пути (`/api/...`) — работает на любом домене.
- Адрес API светофора — env `UROTRIAGE_API_URL`, порт/хост — аргументы uvicorn.
- CORS не нужен: статика и API на одном origin.
- Для домена: тот же запуск за nginx + HTTPS (без HTTPS Android не даст установить PWA и не включится service worker — на localhost исключение, там всё работает).

## 2026-07-05 — правки после теста Фёдора на iPhone

1. **Диагноз больше не предзаполнен.** Было «Острая задержка мочи на фоне ДГПЖ» по умолчанию — Фёдор счёл неправильным. Риск подтверждён: врач сохраняет не глядя, одинаковый текст у всех обесценивает поле. Компромисс: поле пустое, стандартная формулировка вставляется кнопкой «+ ОЗМ на фоне ДГПЖ» одним касанием (правило светофора ищет слова о задержке именно в диагнозе/жалобах, поэтому быстрый ввод сохранён).
2. **Запрет горизонтального свайпа.** Страница уезжала вбок при диагональном движении пальца: `overflow-x: hidden` + `overscroll-behavior-x: none` на html/body.
3. **Отключено масштабирование двойным тапом.** `touch-action: manipulation` глобально + `maximum-scale=1` в viewport. Пинч-зум на iOS остаётся доступен (Safari не даёт его отключить полностью — осознанно, ради доступности).
4. Версия кэша service worker поднимается при каждом изменении статики (`urotriage-v2`), иначе телефоны держат старые файлы.

## 2026-07-05 — автоэкспорт

Вопрос Фёдора: не требуется ли врачу жать «Экспорт», чтобы данные собирались. Нет: сбор идёт в SQLite при каждом «Сохранить». Дополнительно сделан автоэкспорт: `data/анкета_актуальная.xlsx` пересобирается при каждом создании/изменении записи (атомарная запись через .tmp + replace, ошибки экспорта не ломают сохранение). Кнопка «Скачать Excel» осталась как удобство для руководителя. История заполнения общая для всех устройств — осознанно (см. решение «без входа»): исход может дозаполнить врач другой смены.

## Отклонённые идеи

- Отдельная вкладка «Быстрый светофор без сохранения» — отклонена: врачи начнут пользоваться ею вместо записи, и сбор данных провалится. Живой светофор внутри формы даёт то же самое, но данные остаются.
- Пошаговый мастер (wizard) — отклонён, медленнее прокрутки.
- ФИО пациента — отклонено (персональные данные, для модели не нужны).
- localStorage для самих записей — только как офлайн-буфер; основное хранилище на сервере, иначе данные размажутся по телефонам врачей.
