# Urotriage — светофор при острой задержке мочи (ДГПЖ)

Подсказка для врача-уролога: зелёный, жёлтый или красный по острой задержке мочи на фоне ДГПЖ. Зону определяет понятное клиническое правило. Модель работает поверх него как осторожный второй взгляд — она может только перевести зелёный в жёлтый и попросить перепроверить, но красный сама не ставит.


## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

## Из чего состоит

```
src/urotriage/        config, features, cohort, io_data, rule, target, train, explain, service
src/urotriage/api/    FastAPI: main, schemas
scripts/              run_training.py, clean_survey.py, validate_survey.py
docs/                 как устроено, пороги, ответ врача, вопросы врачу, отчёт по модели
tests/                тесты правила, сервиса и API
```

## Данные

Пути лежат в `src/urotriage/config.py`, их можно переопределить через переменные окружения:

- `UROTRIAGE_RAW_XLSX` — большой массив (по умолчанию `../28-12-2025/На_УРОЛОГА (4).xlsx`);
- `UROTRIAGE_SURVEY_XLSX` — анкета пациентов;
- `UROTRIAGE_CORS_ORIGINS` — разрешённые источники для фронтенда через запятую (по умолчанию все).

## Обучение модели

```bash
python scripts/run_training.py
```

Создаёт `models/model_v4.joblib` и `results/results_v4.json` — с метриками и, главное, с разбором того, что модель даёт на зелёных по правилу.

## Запуск API

```bash
uvicorn urotriage.api.main:app --host 0.0.0.0 --port 8000
```

Документация и песочница: `http://localhost:8000/docs`. CORS включён. Если модель ещё не обучена и файла `models/model_v4.joblib` нет — ничего страшного, API поднимется и будет работать на одном правиле.

## Endpoints

- `POST /predict` — один пациент: итоговая зона, что сработало в правиле, что говорит модель, версии.
- `POST /predict/batch` — список пациентов в формате `{"patients": [...]}`.
- `GET /health` — жив ли сервис, загружена ли модель, версии.
- `GET /version` — версии правила, модели, порогов и схемы.
- `GET /schema` — поля на вход, признаки модели, список зон.

### Пример

```bash
curl -X POST http://localhost:8000/predict -H 'Content-Type: application/json' -d '{
  "age": 74, "sex": "Мужской", "temp": 38.4, "creatinine": 156, "crp": 84, "wbc": 14.2,
  "hemoglobin": 128, "diagnosis_text": "ОЗМ на фоне ДГПЖ",
  "imaging_text": "двусторонний гидронефроз", "residual_urine_ml": 650
}'
```

В ответе придёт итоговая зона, разбор по правилу (что и почему сработало), сигнал модели с вероятностью и причиной, версии и оговорки. Логика простая: зону решает правило; если правило дало зелёный, а модель видит риск выше порога — зелёный становится жёлтым с пометкой, что стоит перепроверить.

## Тесты

pytest -q

## Проверка на анкете

```bash
python scripts/clean_survey.py
python scripts/validate_survey.py
```

Это прогон по реальной анкете (45 пациентов) — чтобы убедиться, что ничего не падает и зоны выглядят разумно. Это не клиническая проверка: размеченных вручную случаев зелёный/жёлтый/красный у нас пока нет (см. `docs/doctor_followup.md`).
